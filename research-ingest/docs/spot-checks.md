# Spot-checks — R2 local-model extraction

Deterministic audit of **325 of 3246** extracted videos (10.0 %); every 10th video id in sorted order. Generated by `python3 tools/spotcheck.py` from the runner's batch output `data/kb-extracts.jsonl` — that file is only read.

## Method

`tools/spotcheck.py` reads the exact prompt the model was served from `local_batch/ingest-prompts.jsonl` (channel/title/description + the first ~4 200 caption characters, all timestamped) and checks the answer against that text:

- **papers** — every non-empty `arxiv_id` must appear in the source text (normalised; a malformed or unknown id is a miss);
- **claims** — at least one digit token from the `numbers` field must appear in the source text;
- **timestamps** — a non-null `timestamp` must correspond to a `[MM:SS]` marker in the (truncated) transcript the model saw;
- **shape** — the response parses as one JSON object and has a non-empty `methods` list.

Caveat: the caption chunker merges YouTube auto-captions into long blocks, so many prompts carry only a handful of `[MM:SS]` markers. A timestamp that is not one of those markers is the model guessing a plausible time rather than quoting the transcript; it is flagged, but it does not affect the claim text or the KB.

A **manual deep review** of individual videos, reading the captions next to the model's answer, is in the last section.

### Pipeline limitations found by this audit

1. **Half of the caption-bearing prompts have no transcript.** `prompts.vtt_segments` merges
   YouTube auto-caption cues far too aggressively, so the first merged block can exceed
   `MAX_TRANSCRIPT` (4,200 chars); `transcript_for` then breaks on its first chunk and returns
   `""`. 1,527 of the 3,198 videos that have a VTT were sent description-only. The model
   compensates from memory — which is where the o3 and Napier errors come from. Fix both the
   merge cap and the truncate-first-then-break logic before any future re-ingest.
2. **The instruction example leaks.** `2401.12345` is the schema example in the prompt and
   appears as a "paper" for three videos (a valid-looking id, so the KB keeps it).
3. **Malformed ids are common and safely rejected.** 34 of 666 reported `arxiv_id` values are
   empty, a ResearchGate path, a bioRxiv DOI or similar; `kb.normalize_arxiv` drops them.
4. **Description-only prompts invite unverifiable methods.** Where the transcript was dropped,
   methods cannot be grounded at all, so they should be treated as lower confidence than rows
   whose claims carry a real `[MM:SS]` marker.
